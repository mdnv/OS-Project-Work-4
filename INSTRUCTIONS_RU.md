# MacBook Air M1 → SSH → Ubuntu: потоки и процессы

В архиве готовые скрипты. Все измерения выполнять внутри Ubuntu. На Mac локально выполняются только команды передачи файлов. benchmark.py использует Linux fork и не предназначен для локального запуска на macOS.

## 1. Проверить среду

В существующей SSH-вкладке:

```bash
uname -s
python3 --version
nproc
free -h
```

Ожидается Linux, Python 3.12.x и число доступных VM процессоров. Если Darwin — подключиться обычной SSH-командой. Если Python отсутствует: sudo apt update, затем sudo apt install -y python3 unzip. Пароль sudo при вводе не отображается.

Если nproc=1 или 2, для сравнения желательно выделить VM четыре vCPU: sudo poweroff, затем в VirtualBox выбрать Ubuntu → Settings/Настройки → System/Система → Processor/Процессор → Processor(s)=4 → OK. Запустить VM и переподключиться. Названия зависят от версии. Можно работать и с меньшим числом CPU, но указать это в выводах. Четыре процесса не создают четыре ядра. Настройки между измерениями не менять.

## 2. Передать архив

Скачать os-threads-lab.zip из ответа в Downloads. В Terminal нажать Command+T; новая вкладка работает локально на Mac. Проверить uname -s: Darwin.

```bash
cd ~/Downloads
ls -lh os-threads-lab.zip
```

В командах ниже заменить ПОЛЬЗОВАТЕЛЬ, АДРЕС и порт реквизитами вашей рабочей SSH-команды. Если файл скачан с другим именем, переименовать его через Finder → Загрузки.

Если вы подключаетесь через ssh ПОЛЬЗОВАТЕЛЬ@АДРЕС:

```bash
scp os-threads-lab.zip ПОЛЬЗОВАТЕЛЬ@АДРЕС:~/
```

Если через ssh -p 2222 ПОЛЬЗОВАТЕЛЬ@127.0.0.1:

```bash
scp -P 2222 os-threads-lab.zip ПОЛЬЗОВАТЕЛЬ@127.0.0.1:~/
```

У scp порт задаётся заглавной -P. 2222 — пример, используйте свой порт. Ожидается передача до 100%.

## 3. Распаковать в Ubuntu

Вернуться в SSH-вкладку:

```bash
cd ~
unzip os-threads-lab.zip
cd ~/os-threads-lab
ls
```

Ожидаются benchmark.py, generate_data.py, server.py, memory_demo.py, make_readme.py, README.md, INSTRUCTIONS_RU.md. Если unzip не найден: sudo apt update и sudo apt install -y unzip. Если папка от прошлой работы уже есть, сначала переименовать её в свободное имя, чтобы сохранить результаты. pip и venv не требуются. Просмотреть/редактировать код: nano benchmark.py; сохранить Ctrl+O, Enter; выйти Ctrl+X.

## 4. Создать данные

```bash
python3 generate_data.py
wc -l data/numbers.txt
head -n 3 data/numbers.txt
tail -n 3 data/numbers.txt
wc -l data/urls.txt
```

Ожидается 10 000 000 строк чисел, первые 1, 2, 3, последние 9999998, 9999999, 10000000; 20 строк URL. Контрольная сумма — 50000005000000. Создаются также 20 файлов по 4096 байт в www/.

Если генератор преподавателя обязателен, используйте его вместо нашего; положите numbers.txt в data/ или укажите --numbers ПУТЬ. Для других чисел сумма будет другой: эталон рассчитывается автоматически. Файл должен содержать 10 млн целых чисел, по одному на строку. Генерация выполняется до замеров.

## 5. Измерить сложение

Во время измерений уменьшить фоновую нагрузку на Mac и VM.

```bash
python3 benchmark.py cpu
cat results/cpu_results.md
```

Сначала Loading numbers before timing..., затем Numbers: 10,000,000; reference sum: 50000005000000. Потом девять строк: single, threading, multiprocessing, каждый три раза, все заканчиваются OK. В конце таблица с nproc, тремя временами, медианой и ускорением. Файлы: results/cpu_results.csv и .md.

Файл читается заранее: сравнивается вычислительная часть, без дискового ввода-вывода. Все методы используют одинаковый Python-цикл; каждый из четырёх исполнителей складывает свою четверть. Массив только читается, процессы наследуют его через fork без пересылки 10 млн чисел. Запуск, получение результата и завершение исполнителей включены. Все потоки start вызываются до цикла join. Медиана — среднее по порядку значение трёх отсортированных времён, а не среднее арифметическое.

Процессы могут не ускорить этот конкретный запуск: влияет nproc, размер задачи, фоновые нагрузки, расходы запуска и память. Не заменять реальные цифры ожидаемыми.

## 6. Показать память

```bash
python3 memory_demo.py | tee memory_output.txt
```

Ожидается:

```text
Parent before: []
Inside thread: ['thread']
Parent after thread: ['thread']
Inside process: ['thread', 'process']
Parent after process: ['thread']
```

Изменение потока видно родителю; изменение процесса — только ребёнку. fork первоначально наследует содержимое списка, но не создаёт общий изменяемый список. Linux использует copy-on-write. Обмен между процессами можно организовать явно через Queue, Pipe, SharedMemory.

## 7. Сервер во второй SSH-вкладке

Нажать Command+T на Mac и подключиться обычной SSH-командой. В Ubuntu:

```bash
cd ~/os-threads-lab
python3 server.py
```

Ожидается HTTP server: http://127.0.0.1:8000; delay=0.2s и Stop: Ctrl+C. Терминал остаётся занят — это нормально. Сервер оставить работающим. 127.0.0.1 относится к Ubuntu; пробрасывать HTTP-порт на Mac не нужно.

ThreadingHTTPServer обслуживает запросы одновременно; задержка ответа 0,2 с моделирует удалённый сервер и записана в отчёте. В клиенте искусственного sleep нет. Это эксперимент с моделью задержки, не измерение скорости Интернета.

## 8. Сетевые замеры в первой SSH-вкладке

```bash
cd ~/os-threads-lab
python3 -c "from urllib.request import urlopen; print(len(urlopen('http://127.0.0.1:8000/file01.txt').read()))"
python3 benchmark.py network
```

Проверка выводит 4096. Первые примерно четыре секунды benchmark.py проверяет все URL без строк замеров. Затем девять замеров: sequential, ThreadPoolExecutor и ProcessPoolExecutor, по три раза. Все завершаются OK. Результаты: results/network_results.csv и .md. За запуск скачивается 81920 байт.

Ориентир для задержки 0,2 с: около 4 с последовательно и около 1 с с четырьмя исполнителями. Это оценка, не обязательные цифры. Полная серия с проверкой обычно занимает около 25 секунд.

Если нужен именно обычный http.server без задержки, остановить server.py через Ctrl+C и во второй вкладке запустить:

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory www
```

В первой:

```bash
python3 benchmark.py network --network-note 'python3 -m http.server; no artificial delay'
```

Команда заменит сетевую таблицу. Для сохранения обоих режимов заранее скопировать предыдущие результаты отдельно. На быстром локальном сервере параллелизм может не ускорить загрузку — объяснить это в README. Для списка преподавателя поместить 20 URL в data/urls.txt и указать реальную среду через --network-note. Размеры ответов сверяются с предварительной загрузкой; для динамических страниц содержимое и размер могут меняться. Для воспроизводимости использовать неизменные ресурсы.

## Частые ошибки

| Что вышло | Что сделать |
|---|---|
| Darwin / запрет запуска benchmark.py | Подключиться по SSH; uname -s должен быть Linux. |
| No such file or directory | pwd, ls, затем cd ~/os-threads-lab; проверить имя файла. |
| numbers.txt не найден | python3 generate_data.py. |
| WARNING: expected 10,000,000 | wc -l data/numbers.txt; исправить генерацию и повторить CPU-серию. |
| Connection refused (HTTP) | Запустить python3 server.py во второй SSH-вкладке Ubuntu. |
| Address already in use | ss -ltnp 'sport = :8000'; остановить свой старый сервер Ctrl+C. |
| HTTP Error 404 | Проверить ls www/file01.txt; создать файлы через generate_data.py до замеров. |
| timed out | Проверить сервер и URL; исправить проблему, повторить всю серию. |
| result differs from reference | Проверить неизменность данных/ответов; не сдавать ошибочную серию. |
| Killed | free -h; закрыть лишнюю нагрузку или выделить VM больше памяти. |
| nproc=1 | Указать это в отчёте или до всех замеров выделить больше vCPU. |
| make_readme.py не нашёл results | Сначала benchmark.py cpu и benchmark.py network. |
| scp: Permission denied | Проверить пользователя, адрес, порт и пароль своей рабочей SSH-командой. |
| Времена скачут | Уменьшить нагрузку, повторить полную серию; сохранить три времени и медиану. |

## Ответы для защиты

У потоков общие адресное пространство, код, глобальные данные, куча и файловые дескрипторы. У каждого свои стек, регистры, счётчик команд, состояние и локальные данные потока. Локальное имя может ссылаться на общий объект.

В обычном CPython с GIL один поток интерпретатора выполняет Python-код в данный момент. Поэтому четыре потока не дают параллельное сложение на четырёх ядрах. При ожидании сокетного ввода-вывода GIL освобождается: потоки перекрывают ожидание ответов. У процессов отдельные интерпретаторы и GIL; они могут считать одновременно на доступных CPU, но требуют ресурсов для запуска и обмена результатами. Эти выводы относятся к Python-коду и обычной сборке с GIL; некоторые библиотеки освобождают GIL.

Источники: официальная документация Python 3.12, разделы threading, multiprocessing, concurrent.futures, http.server на https://docs.python.org/3.12/library/.
